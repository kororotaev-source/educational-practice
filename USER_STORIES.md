 
## 1. Описание ситуации

**«В колледже теряется информация об оборудовании»**

В компьютерных классах колледжа числится десятки единиц техники: системные блоки, мониторы, принтеры, проекторы, клавиатуры и мыши. Учёт ведётся разрозненно — в бумажных журналах, Excel-файлах на разных компьютерах и в памяти лаборантов. Из-за этого:

- при перемещении компьютера из кабинета в кабинет информация об этом не фиксируется, и фактическое местонахождение техники расходится с записями;
- принтер, ушедший в ремонт, продолжает числиться «исправным», а списанная техника может до сих пор считаться рабочей;
- при проверке комиссией или инвентаризации приходится тратить часы на сверку и всё равно остаются расхождения;
- при поступлении новой техники легко завести дубль или потерять запись, потому что единого уникального инвентарного номера в учёте нет;
- при смене лаборанта знания о том, где что лежит, уходят вместе с ним.

**Итог:** нет единого, надёжного и проверяемого источника информации об оборудовании. Нужно приложение, которое хранит инвентарные записи в одном месте, позволяет их просматривать, добавлять, искать, изменять и удалять, а также сохраняет данные между запусками.

## 2. Модель карточки оборудования

| Поле (JSON) | Название | Тип | Обяз. | Правило |
|---|---|---|---|---|
| id | Инвентарный номер | int | да |цифр, уникален без учёта регистра |
| type | Тип | str | да | системный блок, монитор, принтер, проектор, клавиатура, мышь |
| name | Наименование | str | да | 2–100 символов, не только пробелы |
| room | Кабинет | str | да | "цифры или буквы" |
| status | Состояние | str (enum) | да | исправно, требует ремонта, списано |
| created_at | Дата постановки | ISO-8601 | авто | ставится при добавлении |
| updated_at | Дата изменения | ISO-8601 | авто | обновляется при изменении |

Первичный ключ — `id`. 

Формат файла данных:

`{"version": 1, "items": [ { ...карточка... }, ... ]}`

## 3. Правила заполнения
id:
- Обязателен, не пустой, без ведущих/замыкающих пробелов.
- Уникален: при добавлении/изменении проверяется по всему списку.
- Рекомендуемый шаблон: Числа больше 0

name:
- Непустое; обрезаются пробелы по краям; длина 1…100.

room:
- Непустой; допускаются цифры и буквы; длина 1…10.

status:
- Только исправно, требует ремонта, списано; иные значения отклоняются.

Общие правила:
- Пустые обязательные поля не принимаются — выводится понятная ошибка, программа не падает.
- Все ошибки валидации выводятся до сохранения; файл data/inventory.json не изменяется при ошибке.
- При старте: если файла нет — создаётся пустой список и файл; если JSON повреждён — сообщение об ошибке, данные не перезаписываются молча.

## 4. Корректные записи

### 4.1. Полный файл с корректными записями

```json
{
  "version": 1,
  "items": [
    {
      "id": 1,
      "type": "системный блок",
      "name": "Dell OptiPlex 3080",
      "room": "каб. 204",
      "status": "исправно",
      "created_at": "2024-09-01T09:15:00+03:00",
      "updated_at": "2024-09-01T09:15:00+03:00"
    },
    {
      "id": 14,
      "type": "принтер",
      "name": "HP LaserJet P1102",
      "room": "каб. 310 (корп. Б)",
      "status": "требует ремонта",
      "created_at": "2024-02-10T11:00:00+03:00",
      "updated_at": "2024-05-12T16:40:00+03:00"
    },
    {
      "id": 27,
      "type": "монитор",
      "name": "AOC 24B1XHS",
      "room": "каб. 204",
      "status": "списано",
      "created_at": "2023-11-20T08:30:00+03:00",
      "updated_at": "2024-06-01T10:05:00+03:00"
    },
    {
      "id": 42,
      "type": "мышь",
      "name": "Logitech M100",
      "room": "каб. 105 (корп. А)",
      "status": "исправно",
      "created_at": "2024-10-03T12:00:00+03:00",
      "updated_at": "2024-10-03T12:00:00+03:00"
    }
  ]
}
```

**Почему корректно:**
- `id` — положительные числа, уникальны.
- `type` и `status` — из допустимых наборов.
- `name` — 2–100 символов, не только пробелы.
- `room` — соответствует `каб. <1–4 цифры>` и опционально ` (корп. X)`.
- `created_at`/`updated_at` — ISO-8601; `updated_at ≥ created_at`.

### 4.2. Пустой файл при первом запуске

```json
{
  "version": 1,
  "items": []
}
```

**Почему корректно:** отсутствие файла при первом запуске не вызывает сбой — создаётся именно такая структура, список считается пустым (US-06).

### 4.3. Минимальная корректная запись (только обязательные поля)

```json
{
  "id": 7,
  "type": "клавиатура",
  "name": "Oklick 100",
  "room": "каб. 5",
  "status": "исправно",
  "created_at": "2024-10-03T12:00:00+03:00",
  "updated_at": "2024-10-03T12:00:00+03:00"
}
```

**Почему корректно:** `created_at`/`updated_at` проставляются автоматически.

## 5. Ошибочные записи

### 5.1 Недопустимый `id`

```json
{
  "id": 0,
  "type": "мышь",
  "name": "Logitech M100",
  "room": "каб. 204",
  "status": "исправно",
  "created_at": "2024-10-03T12:00:00+03:00",
  "updated_at": "2024-10-03T12:00:00+03:00"
}
```

**Почему ошибочна:** `id` должен быть числом больше 0, а здесь `0`. Программа выведет «Инвентарный номер должен быть числом больше 0» и не сохранит запись.

### 5.2 Недопустимое состояние

```json
{
  "id": 15,
  "type": "принтер",
  "name": "HP LaserJet P1102",
  "room": "каб. 310 (корп. Б)",
  "status": "рабочее",
  "created_at": "2024-02-10T11:00:00+03:00",
  "updated_at": "2024-02-10T11:00:00+03:00"
}
```

**Почему ошибочна:** `status` принимает только `исправно`, `требует ремонта`, `списано`, а `рабочее` — вне набора. Программа выведет «Недопустимое состояние. Допустимо: исправно, требует ремонта, списано» и не сохранит запись.

## 6. User Stories с критериями приёмки (6 штук)

---

### US-01. Просмотр списка оборудования

**Критерии приёмки:**
- При выборе пункта «Показать оборудование» выводится список всех записей.
- Для каждой записи видны: инвентарный номер, тип, наименование, кабинет, состояние.
- Если записей нет, выводится сообщение «Список пуст», программа не завершается аварийно.

---

### US-02. Добавление оборудования

**Критерии приёмки:**
- При выборе «Добавить» программа запрашивает поля карточки оборудования.
- Запись с новым уникальным инвентарным номером сохраняется и появляется в списке.
- Нельзя добавить две записи с одним инвентарным номером — выводится понятная ошибка.
- Пустые обязательные поля не принимаются, программа не завершается аварийно.
- Состояние принимает только значения: «исправно», «требует ремонта», «списано».

---

### US-03. Поиск оборудования

**Поиск по инвентарному номеру**
- Поиск по существующему номеру показывает карточку записи.
- Поиск по неизвестному номеру выводит сообщение «Не найдено».
- Ввод пустого номера не приводит к аварийному завершению программы.
- Поиск не изменяет данные и не требует подтверждения.

**Поиск по кабинету**
- Поиск по существующему кабинету показывает все записи этого кабинета.
- Если в кабинете нет оборудования, выводится «Не найдено».
- Поиск по кабинету не зависит от регистра и лишних пробелов по краям.
- Ввод пустого кабинета не приводит к аварийному завершению программы.

**Общие критерии приёмки поиска**
- После вывода результатов программа возвращается в главное меню.
- При поиске по несуществующему значению программа не падает и не очищает список.
- Поиск работает по данным, которые уже загружены в память, и не требует перезапуска.

---

### US-04. Изменение записи

**Критерии приёмки:**
- Программа запрашивает инвентарный номер записи, которую нужно изменить.
- Если номер не найден, выводится «Не найдено», изменения не выполняются.
- Можно изменить кабинет и состояние существующей записи.
- При изменении состояния допускаются только значения: «исправно», «требует ремонта», «списано».
- При изменении кабинета пустое значение не принимается.
- После изменения запись отображается в списке с новыми значениями.
- После перезапуска изменённые данные сохраняются.
- Отмена изменения не меняет запись.

---

### US-05. Удаление записи

**Критерии приёмки:**
- Перед удалением программа запрашивает подтверждение: `Удалить запись? (y/n)`.
- При ответе `n` или пустом вводе запись остаётся в списке, выводится «Удаление отменено».
- При ответе `y` запись удаляется из списка.
- Удаление несуществующего инвентарного номера обрабатывается корректно: выводится «Не найдено», список не меняется.
- После удаления запись исчезает из списка и не появляется после перезапуска.
- Ввод неверного ответа на подтверждение не приводит к аварийному завершению; программа повторяет вопрос или отменяет удаление.
---

### US-06. Сохранение данных между запусками

**Критерии приёмки:**
- Добавленные, изменённые и удалённые записи сохраняются в `data/inventory.json`.
- После перезапуска программы данные загружаются автоматически.
- Отсутствие файла при первом запуске не вызывает сбой, а создаётся пустой список и файл.
- Повреждённый JSON обрабатывается безопасно: программа сообщает об ошибке и не теряет данные незаметно.
