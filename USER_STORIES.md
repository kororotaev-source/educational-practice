 
## 1. Описание ситуации

**«В колледже теряется информация об оборудовании»**

В компьютерных классах колледжа числится десятки единиц техники: системные блоки, мониторы, принтеры, проекторы, клавиатуры и мыши. Учёт ведётся разрозненно — в бумажных журналах, Excel-файлах на разных компьютерах и в памяти лаборантов. Из-за этого:

- при перемещении компьютера из кабинета в кабинет информация об этом не фиксируется, и фактическое местонахождение техники расходится с записями;
- принтер, ушедший в ремонт, продолжает числиться «исправным», а списанная техника может до сих пор считаться рабочей;
- при проверке комиссией или инвентаризации приходится тратить часы на сверку и всё равно остаются расхождения;
- при поступлении новой техники легко завести дубль или потерять запись, потому что единого уникального инвентарного номера в учёте нет;
- при смене лаборанта знания о том, где что лежит, уходят вместе с ним.

**Итог:** нет единого, надёжного и проверяемого источника информации об оборудовании. Нужно приложение, которое хранит инвентарные записи в одном месте, позволяет их просматривать, добавлять, искать, изменять и удалять, а также сохраняет данные между запусками.

## 2. Модель карточки оборудования

| Поле (JSON) | Название | Тип | Обяз. | Правило |
|---|---|---|---|---|
| id | Инвентарный номер | str | да |цифр, уникален без учёта регистра |
| type | Тип | str (enum) | да | системный блок, монитор, принтер, проектор, клавиатура, мышь |
| name | Наименование | str | да | 2–100 символов, не только пробелы |
| room | Кабинет | str | да | "каб. <1–4 цифры>" + опц. " (корп. X)" |
| status | Состояние | str (enum) | да | исправно, требует ремонта, списано |
| serial_number | Серийный номер | str | нет | 3–40 симв., [A-Za-z0-9-] |
| note | Примечание | str | нет | ≤ 300 символов |
| created_at | Дата постановки | ISO-8601 | авто | ставится при добавлении |
| updated_at | Дата изменения | ISO-8601 | авто | обновляется при изменении |

Первичный ключ — `inventory_number`. 

Формат файла данных:

`{"version": 1, "items": [ { ...карточка... }, ... ]}`

## 2а. Правила заполнения
id:
- Обязателен, не пустой, без ведущих/замыкающих пробелов.
- Уникален: при добавлении/изменении проверяется по всему списку.
- Рекомендуемый шаблон: Числа больше 0

type:
- Только из допустимого набора; ввод вне набора отклоняется с сообщением.

name:
- Непустое; обрезаются пробелы по краям; длина 1…100.

room:
- Непустой; допускаются цифры и буквы; длина 1…10.

status:
- Только исправно, требует ремонта, списано; иные значения отклоняются.

note:
- Необязательное; до 200 символов; пустая строка допустима.

Общие правила:
- Пустые обязательные поля не принимаются — выводится понятная ошибка, программа не падает.
- Все ошибки валидации выводятся до сохранения; файл data/inventory.json не изменяется при ошибке.
- При старте: если файла нет — создаётся пустой список и файл; если JSON повреждён — сообщение об ошибке, данные не перезаписываются молча.

## 3. User Stories с критериями приёмки (6 штук)

---

### US-01. Просмотр списка оборудования
Как лаборант, я хочу видеть список всего оборудования, чтобы понимать, что есть в кабинетах.

**Критерии приёмки:**
- При выборе пункта «Показать оборудование» выводится список всех записей.
- Для каждой записи видны: инвентарный номер, тип, наименование, кабинет, состояние.
- Если записей нет, выводится сообщение «Список пуст», программа не завершается аварийно.

---

### US-02. Добавление оборудования
Как лаборант, я хочу добавлять новое оборудование, чтобы учитывать поступления.

**Критерии приёмки:**
- При выборе «Добавить» программа запрашивает поля карточки оборудования.
- Запись с новым уникальным инвентарным номером сохраняется и появляется в списке.
- Нельзя добавить две записи с одним инвентарным номером — выводится понятная ошибка.
- Пустые обязательные поля не принимаются, программа не завершается аварийно.
- Состояние принимает только значения: «исправно», «требует ремонта», «списано».

---

### US-03. Поиск по инвентарному номеру
Как лаборант, я хочу находить компьютер по инвентарному номеру, чтобы быстро узнать, в каком кабинете он находится.

**Критерии приёмки:**
- Поиск по существующему номеру показывает карточку записи.
- Поиск по неизвестному номеру выводит сообщение «Не найдено».
- Ввод пустого номера не приводит к аварийному завершению программы.

---

### US-04. Изменение записи
Как лаборант, я хочу менять кабинет и состояние оборудования, чтобы отражать перемещения и ремонт.

**Критерии приёмки:**
- Можно изменить кабинет и состояние существующей записи.
- Изменения видны в списке и сохраняются после перезапуска программы.
- Попытка изменить несуществующий инвентарный номер обрабатывается корректно — понятное сообщение.
- Нельзя установить состояние вне допустимого набора значений.

---

### US-05. Удаление записи
Как лаборант, я хочу удалять списанное оборудование, чтобы не засорять список.

**Критерии приёмки:**
- Удаление требует подтверждения.
- При отказе от подтверждения запись остаётся в списке.
- Удаление несуществующего инвентарного номера обрабатывается корректно.
- После удаления запись исчезает из списка и не появляется после перезапуска.

---

### US-06. Сохранение данных между запусками
Как лаборант, я хочу, чтобы данные не пропадали после перезапуска, чтобы не вводить всё заново.

**Критерии приёмки:**
- Добавленные, изменённые и удалённые записи сохраняются в `data/inventory.json`.
- После перезапуска программы данные загружаются автоматически.
- Отсутствие файла при первом запуске не вызывает сбой, а создаётся пустой список и файл.
- Повреждённый JSON обрабатывается безопасно: программа сообщает об ошибке и не теряет данные незаметно.
