**Приоритет:** высокий.

**Предусловия:** приложение запущено; в списке есть запись с номером `1` в кабинете `101`, а также записи в других кабинетах.

**Шаги:**

5. Повторить поиск, введя кабинет `999`.

**Ожидаемый результат:**

- По кабинету `101` показываются все записи этого кабинета.
- После каждого поиска программа возвращается в меню и не падает.

**Фактический результат:** *Все работает согласно ожидаемому результату.*

## T-08. Изменение записи и валидация при изменении
**Приоритет:** высочайший.

**Предусловия:** приложение запущено; есть запись с номером `1`.

**Шаги:**
1. Выбрать «Изменение оборудования».
2. Ввести номер `1`, изменить кабинет на `205`, состояние — на `требует ремонта`.
3. Повторить изменение для номера `1`, ввести состояние `рабочее`.
4. Повторить изменение, ввести несуществующий номер `9999`.

**Ожидаемый результат:**
- Корректные изменения применяются и видны в списке.
- Недопустимое состояние отклоняется с понятной ошибкой, запись не меняется.
- По несуществующему номеру выводится «Не найдено», список не меняется.
- Программа не падает и возвращается в меню.

**Фактический результат:** *Корректные изменения применяются. Валидация статуса работает. Выявлен критический дефект: при вводе несуществующего номера (например, в списке есть id=100, но мы уже удаляли элементы из середины, поэтому их всего 70) программа падает с ошибкой IndexError, так как поиск идет по индексу списка, а не по ID.*

**Статус:** *Не пройден.*
