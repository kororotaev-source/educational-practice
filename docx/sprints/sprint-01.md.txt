# Спринт 1 — тест-кейсы и журнал дня (в стиле документа)

## 1. Тест-кейсы Спринта 1 (3 штуки, QA/DevOps)

Спринт 1 проверяет **каркас**: запуск, демо-данные, выход. CRUD ещё не реализован — тесты на него появятся в Спринте 2. Тест-кейсы привязаны к US-01 (частично) и US-06 (частично) и подтверждают DoD дня 1.

---

### T-01. Запуск приложения и отображение главного меню
**Связанная US:** US-01 «Просмотр списка оборудования» (подготовительный шаг).
**Приоритет:** блокирующий.
**Предусловия:** Python 3.11+ установлен; venv активирован; зависимости из `requirements.txt` установлены; проект склонирован из репозитория.

**Шаги:**
1. Открыть терминал в корне проекта.
2. Выполнить `python main.py`.
3. Дождаться вывода меню.

**Ожидаемый результат:**
- Программа запускается без ошибок и трейсбеков.
- Выводится текстовое меню: «Показать оборудование», «Добавить», «Найти», «Изменить», «Удалить», «Выход».
- Отображается приглашение ко вводу.

**Фактический результат:** *(заполняется при прогоне)*
**Статус:** *(Пройден / Не пройден)*
**Комментарий:** Падение при запуске — блокирующий дефект, Спринт 1 не принят.

---

### T-02. Просмотр демонстрационных записей
**Связанная US:** US-01 «Просмотр списка оборудования».
**Приоритет:** высокий.
**Предусловия:** приложение запущено (см. T-01); в `data/inventory.json` лежит ≥5 демо-записей (требование DoD Спринта 1).

**Шаги:**
1. В главном меню выбрать «Показать оборудование».
2. Просмотреть вывод.
3. Вернуться в меню.

**Ожидаемый результат:**
- Выводится список из **не менее 5 записей**.
- Для каждой записи видны: инвентарный номер, тип, наименование, кабинет, состояние.
- Кириллица отображается корректно (не «кракозябры»).
- После вывода программа возвращается в меню, не завершаясь.

**Фактический результат:** *(заполняется при прогоне)*
**Статус:** *(Пройден / Не пройден)*
**Комментарий:** Записей < 5 — DoD Спринта 1 не выполнен; «кракозябры» — проблема с `encoding='utf-8'` при чтении файла.

---

### T-03. Корректный выход из приложения
**Связанная US:** US-06 «Сохранение данных между запусками» (частично — проверка, что выход не повреждает файл).
**Приоритет:** средний.
**Предусловия:** приложение запущено (см. T-01); выполнены любые действия в меню (например, просмотр списка).

**Шаги:**
1. В главном меню выбрать «Выход».
2. Проверить код возврата: `echo $?` (Linux/macOS) или `echo %ERRORLEVEL%` (Windows).
3. Повторно запустить `python main.py`.

**Ожидаемый результат:**
- Программа завершается без трейсбека и сообщений об ошибках.
- Код возврата — `0`.
- Повторный запуск снова показывает меню; файл данных не повреждён.

**Фактический результат:** *(заполняется при прогоне)*
**Статус:** *(Пройден / Не пройден)*
**Комментарий:** Ненулевой код возврата или трейсбек — дефект; ошибка чтения JSON при повторном запуске — дефект хранения (готовим почву для Спринта 4).

## 2. Журнал Спринта 1 (план / результат / ошибки / передача ролей)

### План спринта
**Цель дня:** определить требования, подготовить репозиторий и каркас приложения.
**Роли (Спринт 1):** А — PO, Б — LD, В — QA/DevOps.

**Задачи по ролям:**
- PO (А): описать ситуацию «в колледже теряется информация об оборудовании»; составить ≥6 User Stories с критериями приёмки.
- LD (Б): создать структуру проекта (`main.py`, `inventory.py`, `storage.py`, `data/`, `tests/`); набросать меню и модель записи; реализовать пункт «Показать оборудование» на демо-данных.
- QA (В): настроить Python и pytest; создать Git-репозиторий и `.gitignore`; проверить запуск на другом компьютере; оформить первые 3 тест-кейса (T-01…T-03).

### Результат спринта
- Рабочее меню, файл требований (`USER_STORIES.md`), список задач.
- Первый коммит каждого участника.
- `README.md` с назначением проекта.
- `data/inventory.json` с ≥5 демо-записями.
- Оформлены тест-кейсы T-01, T-02, T-03.

### Definition of Done — статус
- [x] Меню запускается.
- [x] Требования проверяемы (≥6 User Stories с критериями приёмки).
- [x] Проект открывается из репозитория.
- [x] Есть ≥5 демонстрационных записей.

### Ошибки и замечания
*(заполняется по факту прогона)*
- Пример: T-02 не пройден — в `inventory.json` 4 записи вместо 5. Исправление: добавить демо-запись, повторить прогон.
- Пример: при повторном запуске после «Выхода» — `JSONDecodeError`. Причина: файл открывался на запись без `encoding='utf-8'`. Исправление: указать кодировку в `storage.py`.

**Что не готово:** *(по факту)*
**Ошибки:** *(по факту)*
**План на завтра (Спринт 2 — «Оборудование под контролем»):**
- PO (Б): уточнить поля карточки, правила заполнения, критерии приёмки; подготовить примеры корректных и ошибочных записей.
- LD (В): реализовать добавление записи и вывод списка; проверка уникальности инвентарного номера; выделить функции для тестирования.
- QA (А): написать pytest-тесты на успешное добавление, пустые поля, повторяющийся номер; проверить изменения через отдельную ветку и слияние.

**Новые роли со Спринта 2:** А — LD, Б — QA/DevOps, В — PO.

Если нужно — могу так же оформить журнал Спринта 2 с тест-кейсами под добавление и валидацию (уже с pytest-скелетом `tests/test_inventory.py`).
