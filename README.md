# Система учёта инвентаря компьютерных классов

Консольное приложение на Python для ведения инвентарных записей компьютерного оборудования колледжа.

## Возможности

- просмотр всего оборудования;
- добавление записи с автоматическим назначением уникального инвентарного номера;
- поиск по номеру, типу, наименованию, кабинету и состоянию;
- изменение типа, наименования, кабинета и состояния;
- удаление записи с подтверждением;
- сохранение данных в JSON и загрузка при следующем запуске;
- проверка обязательных полей и допустимых состояний;
- безопасная обработка отсутствующего, пустого и повреждённого файла;
- автоматические тесты `pytest`.

## Требования

- Python 3.11 или новее;
- `pip`;
- терминал;
- Git — для получения исходного кода и командной разработки.

## Установка и запуск

Откройте терминал в каталоге проекта.

### Windows

```powershell
py -3 -m venv .venv
.venv\\Scripts\\activate
python -m pip install -r requirements.txt
python main.py
```

### Linux / macOS

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

Если виртуальное окружение создавать не требуется, достаточно установить зависимости командой `python -m pip install -r requirements.txt` и запустить `python main.py`.

## Главное меню

| Пункт | Действие |
|---|---|
| 1 | Показать оборудование |
| 2 | Добавить оборудование |
| 3 | Поиск оборудования |
| 4 | Изменение оборудования |
| 5 | Удаление оборудования |
| 0 | Выход |

При вводе `0` во время заполнения формы или выбора записи текущая операция отменяется.

### Добавление

Пользователь вводит тип, наименование, кабинет и состояние. Номер назначается автоматически: на единицу больше максимального существующего номера. Состояния: `исправно`, `требует ремонта`, `списано`; также доступны варианты `1`, `2`, `3`.

### Поиск

Поиск выполняется по инвентарному номеру, типу, наименованию, кабинету или состоянию. Сопоставление текста не зависит от регистра и выполняется по вхождению подстроки.

### Изменение

По номеру выбирается запись; можно изменить тип, наименование, кабинет или состояние. Инвентарный номер не редактируется. При изменении обновляется поле `updated_at`.

### Удаление

Перед удалением программа показывает номер и наименование. Ответ `y` подтверждает удаление; любой другой ответ отменяет его.

## Хранение данных

Файл данных: `data/inventory.json`.

Формат:

```json
{
  "version": 1,
  "items": [
    {
      "id": 1,
      "type": "Монитор",
      "name": "Samsung S24",
      "room": "204",
      "status": "исправно",
      "created_at": "2026-09-01T09:15:00+03:00",
      "updated_at": "2026-09-01T09:15:00+03:00"
    }
  ]
}
```

`id` — положительное целое число, назначается приложением. `created_at` и `updated_at` записываются в формате ISO 8601 с часовым поясом. Старые записи без `updated_at` при загрузке получают значение `created_at`.

При первом запуске отсутствующий файл создаётся автоматически. Пустой файл трактуется как пустой список и приводится к корректному JSON. Повреждённый или структурно некорректный файл не перезаписывается молча: приложение выводит ошибку и прекращает запуск до исправления файла.

## Тестирование

Установите зависимости, затем из корня проекта выполните:

```bash
python -m pytest -v
```

Тесты используют временный файл данных и не изменяют `data/inventory.json`.

## Ограничения

- Интерфейс только консольный.
- Данные хранятся в локальном JSON-файле; СУБД и одновременная многопользовательская работа не поддерживаются.
- Автоматическое восстановление повреждённого JSON не выполняется: файл нужно исправить вручную или восстановить из резервной копии.
- Docker не включён в обязательный сценарий запуска.
